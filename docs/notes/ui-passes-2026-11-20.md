# Five UI/UX passes (2026-11-20/21, web + desktop + Android)

Jack asked for five UI/UX passes over the website, the desktop app and the phone app, each graded
1–10 with the fixes the reviewers asked for. Each pass had a reviewer (screenshots only, no code)
and a separate fixer per platform: web + desktop (headless Chromium at 1440/390, light/dark; the
desktop frontend under Vite) and Android (the `sheddex` emulator with the debug app on Metro). Each
pass had a focus: 1 first look, 2 Library/Files/PDF, 3 tools and Shed Log, 4 people/account/first
run, 5 a whole-app sweep. Details of every fix are in the notes files the fixers wrote (ux-refresh,
pdf-editor, library-two-tabs, lessons, community-and-profiles, desktop-app, web-ui-patterns,
shed-log, mobile-refresh).

## Bugs the passes found (beyond polish)

- Desktop: blank window under Vite dev (the pdf.js worker alias) — fixed with a relative import.
- PDF editor: Escape on a popover closed the editor; Escape while typing dropped the text.
- Phone app: it didn't know the Library tune list and its "Unlink" was undone by the web; now on
  the web's model (Library list, delete-not-unlink, new charts join their tune, Recordings in Files).
- Phone app: ear trainers kept running (and grading) under other screens; the Practice Timer pill
  covered tool options.
- Phone app (privacy): a new account saw the previous account's local settings/favourites/recents —
  local stores are now per account (`lib/accountScope.ts`) with a one-time move of old data.
- Phone app: reopening the app could lose a pending write and even sign you out — account writes now
  wait for the backend's sign-in (`sendToAccount`).
- Web: a teacher's student page overflowed sideways on phones; lesson dialog buttons fell off-screen.
